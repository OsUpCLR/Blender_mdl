# SC Model IEX — частые вопросы

SC Model IEX — частые вопросы
==========================

УСТАНОВКА
1. Add-ons -> Install -> папка SC_MODEL_IEX (или zip).
2. Включить «SC Model IEX».
3. Настройки аддона: «Корень игры (data)» = ...\\star conflict\\data
   (там gamedata/def/ex/ship.lua, ship_dyes.lua, ship_armors.lua).
   «Распакованное дерево» = the game .pak files (оттуда берутся текстуры,
   которых нет россыпью в data, например броня и кристаллы).
   sc_tools уже встроен в аддон — ничего указывать не нужно.

ПОВТОРНЫЙ ИМПОРТ (сцена не очищается)
* Перед импортом аддон НЕ удаляет объекты из сцены — ни дефолтный куб, ни
  результаты прошлых импортов. После импорта той же модели в сцене будет две
  копии (старая и новая), новые объекты получат имена с `.001`, `.002`.
* Почему так: раньше аддон сам удалял объекты прошлых импортов этой модели по
  префиксу имени, из-за чего нельзя было сравнить два импорта или держать
  рядом несколько вариантов корабля.
* Как получить чистую сцену: File -> New -> General (или удалить объекты
  вручную: A, X, Enter). Перед импортом удалите дефолтный куб, иначе он попадёт
  в кадр и в экспорт.

КНОПКА «FAQ: ИМПОРТ И ЭКСПОРТ»
* Открывает этот файл в новом окне Blender (редактор текста). Если окно
  создать нельзя — в существующем редакторе текста или разделив 3D-вид;
  в крайнем случае открывает FAQ.md системным приложением или копирует
  текст в буфер обмена с путём к файлу.

ИМПОРТ
* Модель: File -> Import -> Star Conflict model (.mdl-hdr).
* Из пака: File -> Import -> Star Conflict model from .pak.
* LOD: -1 = все уровни, 0 = самый подробный.
* Части (_eng/_cap/_boost) собираются галочкой; скелет — отдельной.
* Покраска: _d — альбедо, _s1 — МАСКИ трёх слоёв (R/G/B), цвет слоя берётся
  из def-а корабля (default_custom_elements -> ShipDyes.albedo).
* Детали: список «Детали» — «Все части + привязка к костям» (по умолчанию),
  «Все части без привязки», «Только эта модель (без частей)». В импорте из пака
  есть ещё список «Части из других паков»: «Догружать» / «Не догружать».
* Броня (тёмный металл у деталей): «Паттерн брони (ShipArmors)», например
  Crossout_Armor02; по умолчанию выключена, потому что в игре паттерн
  выбирается per-instance и в файлах его нет.
* Кристаллы Эллидиума: у кораблей Race5 _s1 в DXT5, альфа — маска кристаллов.
  Аддон пишет в лог «кристаллы: N%» и ставит obj["sc_model_iex_crystals"].
  ВАЖНО: цвет кристалла НЕ из текстуры (per-instance UserParam4), поэтому
  визуально кристаллы сейчас рисуются как обычная покраска.

МАТЕРИАЛЫ (как в object.fx)
Диффуз — _d; _glow — свечение; _nm — DXT5nm (A=X, G=Y, R=AO); _sc — блик,
альфа = глянец; _pdo — затенение (UV2); _msk — G=AO, B=глянец.
Цвета красителей переводятся из sRGB в линейное — иначе корпус светлеет,
а непокрашенные детали остаются чёрными.

ОСОБЕННОСТИ BLENDER 5.2
* Кастомные нормали из файла не задаются — Blender считает свои.
* _nm/_sc/_pdo грузятся как Non-Color.
* Сцена НЕ очищается: перед импортом удалите дефолтный куб
  (select_all -> delete), иначе он попадёт в кадр.
* Вид «сверху, нос вверх» (Numpad 7): +X — вправо, совпадает с игрой.

ЭКСПОРТ
* Режимы: folder (файлы), new_pak (архив), «дописать/дописать с заменой».
* Круг импорт -> экспорт без правок: 54/54 файла побайтово.
* Части из других паков (Phoenix: capacitor в misc.pak, бустеры в
  models_ships_race_4_l.pak) в пак корпуса НЕ попадают (иначе «2 и более
  одинаковых копии»). Их правки сохраняются галочкой «Пересобрать паки частей
  из других паков» (обновляет их пак с .bak), иначе в лог пишется, где деталь.
* Деплой: закрыть игру -> бэкап исходного .pak -> положить новый пак
  ПОД ИСХОДНЫМ ИМЕНЕМ -> запуск. Откат — вернуть бэкап.

ЧАСТЫЕ ПРОБЛЕМЫ
* «текстура не найдена» — проверьте «Корень игры» и «Распакованное дерево».
* Модель тёмная — это покраска/свет; включите «Свет как в игре».
* В игре правка на другом борту — старое поведение до исправления зеркала;
  текущая версия зеркалит оси как игра (проверено на _boost).
* Анимации крутятся наоборот — сообщите, поправим знак кватерниона.
